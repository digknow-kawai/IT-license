# IT資産・ライセンス 定期棚卸 照合ツール（VBAソース）

人事マスタ・IT資産台帳・資産管理ツールのインベントリ・ライセンス契約を突き合わせ、差異（退職者の端末、異動の反映漏れ、所在不明、台帳にない機器、ライセンスの過不足など）を洗い出して、部門への確認依頼と台帳の更新につなげるExcelマクロのソースです。

## 構成

| パス | 内容 |
|---|---|
| `src/vba/M00_Main.bas` | 全体の実行制御（ボタン①②の入口） |
| `src/vba/M01_Import.bas` | インプットExcelの取込（見出し名で列を対応付け）と突合キーの整形 |
| `src/vba/M02_Match.bas` | 資産台帳・インベントリ・人事マスタの突合と差異判定 |
| `src/vba/M04_License.bas` | ライセンス過不足・サマリの作成（数式） |
| `src/vba/M05_Request.bas` | 部門別確認依頼リストの作成 |
| `src/vba/M06_Log.bas` | 実行ログと保管コピーの作成 |
| `src/vba/M07_Sheets.bas` | 出力シート（OUT_／LOG_）の自動生成 |
| `src/vba/ThisWorkbook.cls` | ブックを開いたときに実行ボタンを配置 |
| `tools/M99_Export.bas` | ブック内のモジュールを `src/vba` へ一括エクスポートする補助マクロ |

## 処理の流れ

1. 表紙に棚卸基準日を入力する
2. ボタン① `Main_RunInventory`：インプットExcelを選択 → 取込・整形 → 突合・差異判定 → ライセンス集計・サマリ（`OUT_照合結果`／`OUT_ライセンス過不足`／`OUT_サマリ` を自動生成）
3. 担当者レビュー：`OUT_照合結果` の担当者コメントに「除外」と書いた行は、確認依頼の対象外になる
4. ボタン② `Step2_ExportRequests`：`OUT_部門別確認依頼` を作成し、保管コピーを保存する

## ブックの前提

- シート `00_表紙`（基準日は B7）と、取込先の `IN_人事マスタ`／`IN_資産台帳`／`IN_インベントリ`／`IN_ライセンス契約`／`IN_ソフト利用実績` が必要です。見出しは4行目、データは5行目からです。
- インプットExcelには、`人事マスタ`／`資産台帳`／`インベントリ`／`ライセンス契約`／`ソフト利用実績` の5シートが必要です。1行目を見出しとし、列の順番は問いません。

## 開発の流れ

1. ブックのVBAを修正する
2. `tools/M99_Export.bas` をブックにインポートし、`ExportModules` を実行して `src/vba` に書き出す
   - 事前に［トラストセンター］→［マクロの設定］→「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」をオンにする
3. `git diff` で差分を確認してからコミットする

ソースからブックへ取り込むときは、VBE（Alt+F11）の［ファイルのインポート］で `src/vba` の各ファイルを読み込みます。`ThisWorkbook.cls` は、中身を既存の ThisWorkbook モジュールに貼り付けてください。

## 文字コード

VBEのエクスポート形式（Shift-JIS／CRLF）のまま作業できるように、`.gitattributes` で `working-tree-encoding=CP932` を指定しています。リポジトリの中はUTF-8で保存されるので、GitHub上でも日本語が文字化けしません（Git 2.18以降が必要）。

## 注意

- 人事マスタや実際の資産台帳など、**実データはコミットしないでください**（個人情報を含むため）。
- 判定の閾値（長期未通信の日数、リース満了警告の日数、ライセンス余剰率など）は、各モジュール先頭の `Const` で定義しています。
